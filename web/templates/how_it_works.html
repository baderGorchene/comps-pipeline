How it works

You give the tool an MLS export and the house you're appraising. It narrows hundreds of listings down to {{ summary.sold_count }} sold comps and {{ summary.listing_count }} active listing, and tells you why at every step. The numbers below are your current settings.

The short version
  1. Read your file
  2. Clean it up
  3. Measure each property
  4. Apply your rules
  5. Rank the best matches
  6. Check the photos (optional)
  7. Pick the final comps
  8. Explain everything

Steps 1–5 and 7 follow fixed rules: the same file and settings always give the same answer. AI only writes the explanations and, if turned on, checks photos.

1

Read your file

Your MLS export can use any column names. The tool matches them to {{ summary.mapped_fields }} standard fields (price, square feet, year built, …) using the list in Settings → CSV columns. Columns it doesn't know are kept but not used for rules.

2

Clean it up

  • Removes duplicate MLS numbers and rows missing must-have values.
  • Splits the rest into sold and active / option / pending. Expired, withdrawn and cancelled listings are dropped.
  • Reads the listing remarks for clues: distressed sale, lease or tenant, garage conversion, guest house (ADU), solar lease, waterfront or highway, and condition words.
3

Measure each property

  • Distance to the house, from map coordinates or the file's distance column.
  • Subdivision match: same name, a known alias, a close spelling (flagged for you to check), or a different subdivision.
  • How different the living area, lot and age are from the subject.
4

Apply your rules

A property must pass all of these to stay:

  • Living area within ±{{ summary.gla_pct }}% of the subject
  • Lot size within ±{{ summary.lot_pct }}%
  • Within {{ summary.max_miles }} miles
  • Sold in the last {{ summary.max_months }} months

  • Price within ±{{ price_pct }}% of the subject's contract or estimated value

  • Same subdivision only

5

Rank the best matches

Sold and active comps are ranked separately. Comps are compared on the first item below; if they're close enough to count as a tie, the next item decides, and so on.

    {% for r in ranking %}
  1. {{ r.name }} — {{ r.tie }}
    2. {% endfor %}

The top {{ summary.shortlist_size }} sold and {{ summary.listing_shortlist_size }} active become the shortlist.

6

Check the photos {% if vision.enabled %}On{% else %}Off{% endif %}

If turned on, an AI model looks at up to {{ vision.max_photos_per_property|default:25 }} listing photos of each shortlisted comp and the subject, and rates condition (C1–C6) and quality (Q1–Q6).

  • Comps whose photos are {{ vision.rerank_min_delta|default:2 }}+ rating steps away from the subject move down the shortlist. Others keep their place.
  • Scores below {{ vision.min_confidence|default:0.6 }} confidence are recorded but never move a comp.
  • If the photos contradict the remarks (e.g. “renovated kitchen” but old cabinets), you get a warning.

Only the shortlist is checked, never the whole file, to keep it fast and cheap. Needs an AI key and a photo URL column. Turn on with vision.enabled in settings.yaml.

7

Pick the final comps

The top {{ summary.sold_count }} sold and {{ summary.listing_count }} active comps are picked. Then the tool checks bracketing: for each of {{ summary.brackets|join:", " }}, at least one pick should be above the subject and one below.

Example: the subject is 2,000 sq ft. Picks of 1,850 and 2,150 bracket it. Picks of 2,100 and 2,300 do not — every comp is bigger.

If something isn't bracketed, the tool swaps in the next-best shortlisted comp that fixes it. If none can, you get a warning.

New construction is different

For a brand-new subject (C1), picks are split: 2 sold + 1 active inside the subject's subdivision, 1 sold + 1 active from competing subdivisions, plus 1 more sold. New builds with tenants or private owners are flagged, since they may really be C2.

8

Explain everything

  • Each pick gets a one-line reason it was chosen.
  • Each shortlisted comp that wasn't picked gets a reason it was left out.
  • An AI summary describes the whole run in plain English.
  • Anything unusual becomes a warning: Blocking means the run couldn't finish properly, Review means check it, Info is just good to know.

Every decision is saved to the run's files (audit.jsonl, flags.csv, …) so you can show your work.

Standard condition and quality ratings. C1 is new, C6 is poor; Q1 is the best build quality.

Loosening the rules automatically when too few comps pass.
